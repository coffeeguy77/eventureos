## Tenant security model

- Every tenant table has `organisation_id`. RLS policies allow access only when the signed-in user is an active member of that organisation (`is_org_staff`, `is_org_manager` helpers).
- Relationships use **composite foreign keys** `(id, organisation_id)`, so a record can never point at another tenant's customer, event or quote — even with a crafted request.
- Customers (portal role) cannot read staff data. Only managers and above can delete. The audit log is append-only.
- Published quote versions are immutable (enforced by a database trigger).
- Integration tokens live in `integration_credentials`, which no client role can read.
