# Local setup

[Wiki](index.md) · [Configuration](configuration.md) · [Deployment](deployment.md) · [Data model](data-model.md)

The app runs locally. The database does not. Queries go to the hosted Supabase project in `.env.example` (name `eventureos`, region `ap-southeast-2`). There is no `supabase start` config in this repository.

## What you need

- Node.js 20 or newer
- npm
- The environment variables in `.env.example`. The two `NEXT_PUBLIC_SUPABASE_*` values are enough to sign in and read data. Integrations, email, cron and AI need the server secrets as well. See [Configuration](configuration.md)

## Install and run

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open the URL Next prints (port 3000 unless that port is taken). Sign in with a demo user below, or with an account you already have on that Supabase project.

`npm run dev` is `next dev`. `npm run typecheck` is `tsc --noEmit`. `npm run build` is `next build`. Contributors sharing one working tree are asked, in `docs/CONVENTIONS.md`, not to run `next build` while others are using the folder, and not to add npm packages without a reason.

## Where to look when a page is empty

- Missing `NEXT_PUBLIC_SUPABASE_URL` or `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: the app throws, and middleware returns a 500 that names the variables.
- Signed in but sent to `/onboarding`: the user has no active office membership. Accept an invite, or create an organisation.
- Sent to `/suspended`: the organisation status is not active.
- Sent to `/p/<slug>`: the membership role is `customer`.
- Sent to `/crew/<slug>`: the login is on `crew_members` and is not an office user.
- A menu item missing: the role cannot open it, a section list hides it, or the app is locked. Owners see every app the business is allowed. Hosting and Nerd Herd are off until a platform admin grants them.
- Gmail, Calendar or Xero will not connect: the Google or Xero client id and secret are empty, or the OAuth state secret is empty. The integrations page lists the missing names. The redirect URI has to be registered on the provider for the `APP_URL` you are using. `http://localhost:3000` is a different URI from production.

## Tests

Domain logic that can be checked without a database lives next to the code as `*.test.ts` files (quotes, kitchen, bookings, invoices, mail rules, and others). They use Node’s built-in test runner (`node:test`). There is no `npm test` script and no TypeScript test runner in `package.json`. `npm run typecheck` is the check the project scripts define.

## Engineering conventions

[docs/CONVENTIONS.md](../CONVENTIONS.md) is the short version of how queries, RLS, activity logs, server actions and the UI are written. Read it before changing the product. New tables need RLS. New migrations are additive files under `supabase/migrations`. The service-role key does not belong in a page that already has a signed-in user.
